# 公共知识库上传第一版实施报告

日期：2026-07-16

## 1. 完成结论

公共知识库上传第一版已完成并通过真实环境验收。浏览器可以在“知识库管理”页面上传公开法规、公开案例和工作资料；平台 API 将原件保存到 MinIO、登记 `sys_attachment` 与 `kb_document`，随后通过 FastAPI 执行真实解析、切片、BGE-M3 向量化和 Milvus 写入。

本版本仍是可信局域网、无登录版本，不包含案件私有材料、批量上传、删除、版本管理和用户权限。正式对公网开放前，必须先完成登录、JWT/Session、用户身份注入与 RAG 权限联调。

## 2. 调用链

```text
浏览器 :5173
  → POST /api/rag/documents
law-platform-api :3000
  → SHA-256、格式校验、MinIO 原件、数据库登记
  → POST /documents/{id}/ingest
law-rag-kb :8000
  → Markdown/图片解析 → BGE-M3 → Milvus → 状态回写
```

浏览器只访问相对路径 `/api/rag/*`。FastAPI 地址、内部服务 Token、PostgreSQL、Milvus 和 MinIO 凭据均不会进入前端代码或浏览器请求。

## 3. 已实现功能

### 3.1 平台 API

| 路由 | 用途 |
|---|---|
| `POST /api/rag/documents` | multipart 上传原件，登记公共知识库文档 |
| `GET /api/rag/documents` | 按标题、分类、入库状态分页查询 |
| `POST /api/rag/documents/{id}/ingest?force=` | 自动入库、失败重试或强制重建 |
| `GET /api/rag/documents/{id}/status` | 查询切片数、图片数和入库状态 |
| `GET /api/rag/documents/{id}/markdown` | 查看 FastAPI 生成的规范 Markdown |
| `GET /api/rag/documents/{id}/chunks?page=&page_size=` | 分页查看 Milvus 中的 Chunk 正文与 metadata，不返回向量 |

入库接口单独使用 `RAG_INGEST_TIMEOUT_MS=900000`，检索和问答仍使用 `RAG_API_TIMEOUT_MS=120000`。平台只从服务端读取 `RAG_SERVICE_TOKEN`，不会转发浏览器自定义认证头。

### 3.2 文件规则与一致性

- 单文件上限 50MB。
- 支持 PDF、DOCX、TXT、MD、PNG、JPG/JPEG、WebP、BMP、TIF/TIFF。
- 同时校验扩展名、浏览器 MIME 和文件签名/UTF-8 文本，拒绝伪装或损坏文件。
- MinIO 键位于 `knowledge-base/{年}/{月}/{hash前缀}/...`。
- MinIO 上传成功后，附件和知识文档在同一数据库事务中创建；事务失败会补偿删除刚上传的对象。
- `uploaded_by`、`created_by` 在无登录版本中保持 `NULL`，不伪造员工 ID。

### 3.3 内容哈希去重

上传前计算原件 SHA-256。相同哈希的活动 `knowledge_base` 附件会返回已有文档，并设置 `deduplicated=true`，不再次上传和向量化。

Alembic 迁移 `b6c7d8e9f0a1` 增加活动公共知识库附件的部分唯一索引，可阻止并发请求创建重复哈希。历史附件的 `file_hash` 为空，不做批量回填，因此历史批量样本文档不自动参与本规则。

Alembic 迁移 `c7d8e9f0a1b2` 在 `oa.kb_document` 增加 `upload_timings` 与 `ingest_timings` 两个 JSONB 字段。每份文档只保存最近一次记录：新文件上传保存上传登记耗时，真实入库或强制重建覆盖入库耗时；重复上传不覆盖已有记录。平台通过参数化原生 SQL 读写这两个字段，没有引入 Prisma Migrate 或修改 Milvus collection schema。

### 3.4 前端管理页

- 第三个页面标签“知识库管理”。
- 上传后自动登记、调用入库并每 3 秒查询状态，最长等待 15 分钟。
- 明确展示等待、处理中、成功、失败和重复文件状态。
- 支持标题/分类/状态筛选、分页、状态刷新、失败重试和强制重建。
- 支持安全 Markdown 预览；不渲染原始 HTML，也不加载 Markdown 内的 MinIO 图片 URL，避免浏览器绕过平台网关直连 9000。
- “查看 Chunk”与“查看 Markdown”互斥；Chunk 预览展示 ID、序号、字符数、正文、法条号、章节、页码、内容类型与图片 metadata，并支持每页 20 条翻页。
- 文档卡片可展开“处理耗时”，分别展示上传登记与 RAG 入库的准确分阶段耗时；小于 1 秒显示毫秒，否则显示秒。历史文档没有记录时明确提示强制重建后生成，不使用估算值。
- 入库按 Milvus 准备、原件解析、清理去重、draft、VL、摘要、最终切片、Embedding、Milvus 写入、状态回写共 10 个阶段记录；无图片时 VL 阶段显示“已跳过”。
- 第一版没有删除按钮和删除 API。

## 7. 多源文件追加与源文件级安全替换

早期的卡片级“替换文件”和常驻“继续上传”仅适用于单文件文档，语义容易混淆，现已由多源文件模型取代。顶部上传区只创建新的独立知识库，按钮统一为“新建并自动入库”；已入库卡片通过“追加文件”把后续原件加入同一 `doc_id`。

### 7.1 数据模型与迁移

Alembic `d8e9f0a1b2c3` 新增 `oa.kb_document_source`：

- 一条记录代表一份知识库源文件，保存附件、来源标题、显示顺序和主文件标记。
- 分别保存该来源的入库状态、Chunk/图片统计、Markdown、摘要、上传 timing 和入库 timing。
- 迁移为每个现有 `kb_document.attachment_id` 回填主来源；`kb_document.attachment_id` 继续作为主文件兼容字段。
- 活动附件哈希唯一性同时覆盖主文件和追加文件；staging 附件不占用活动唯一索引。

Node 平台仍不使用 Prisma Migrate，新表通过参数化原生 SQL 访问。

### 7.2 接口与安全流程

| 路由 | 用途 |
|---|---|
| `GET /api/rag/documents/{id}/sources` | 查询文档的全部有效源文件和各自统计/耗时 |
| `POST /api/rag/documents/{id}/sources` | 每次追加一个后续文件，来源标题默认文件名 |
| `PUT /api/rag/documents/{id}/sources/{sourceId}/file` | 只替换选中的源文件 |
| `GET /api/rag/documents/{id}/markdown?source_id=` | 合并查看或按来源查看 Markdown |
| `GET /api/rag/documents/{id}/chunks?...&source_id=` | 合并查看或按来源查看 Chunk |

追加和替换都先建立隐藏附件/文档，在 FastAPI 中完成真实解析、摘要、Embedding 和 Milvus 写入。成功提升后，新 Chunk 使用 `{doc_id}:s:{source_id}:m:{source_chunk_idx}`（图片使用 `i` 类型），metadata包含来源 ID、标题、文件名和来源内序号；原 Chunk 不因追加而删除。任一步骤失败都会恢复原 Milvus 数据并清理 staging。

“强制重建”对全部有效来源逐一建立不可见 staging；只有所有来源均成功后，才一次性替换目标文档的完整 Chunk 集合。追加、单来源替换和全量重建共用文档级单实例内存锁，并发操作返回安全 `409`。
