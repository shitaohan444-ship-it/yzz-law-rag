## 3. 发现的问题与风险

### P2：容器内阶段测试脚本不可直接完整运行

表现：

1. `TestClient` 的 Host `testserver` 不在 `TRUSTED_HOSTS`，首次 `/health` 返回非 JSON。
2. 放行测试 Host 后，脚本在 D 阶段访问 `/test_files/法律法规/民法典合同编.md`，但 RAG 容器没有挂载 `/test_files`，出现 `FileNotFoundError`。

影响：产品 API 不受影响，但容器内无法一条命令执行完整 `run_stage_tests.py`。

建议：

- 测试脚本显式创建 `TestClient(app, base_url="http://localhost")`，或测试配置加入 `testserver`。
- 在专用 test compose 中只读挂载 `./test_files:/test_files:ro`，不要污染生产 compose。
- 将阶段脚本拆成不依赖宿主路径的 API 测试与独立入库 fixture。

### RESOLVED：PowerShell 5.1 向 Python stdin 传中文的编码风险

表现：中文源码通过 here-string 管道传给 `python -` 时变为问号。

处理结果：

- 新增 `law-rag-kb/scripts/Invoke-PythonUtf8.ps1`。
- 实测完整中文法律问题可无损进入 Python，`sys.stdin.encoding` 和 `sys.stdout.encoding` 均为 `utf-8`。
- 实测 `-Code` 参数和 PowerShell 对象管道两种调用方式均通过。
- 实测执行结束后 `$global:OutputEncoding`、Console Encoding 和 `PYTHONIOENCODING` 均恢复原值。

后续约束：正式测试优先执行 UTF-8 `.py` 文件；临时中文 stdin 代码必须通过该包装器；PowerShell HTTP JSON 继续使用 `[Text.Encoding]::UTF8.GetBytes()`。
