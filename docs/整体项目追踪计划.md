# 律所 OA 系统整体项目追踪计划

> 本文档用于追踪 `law-rag-project` 律所 OA 系统从数据库设计到业务功能落地的整体进度。
> 最后更新：2026-07-22

---

## 1. 项目概述

### 1.1 目标

建设一套覆盖律所全业务流程的 OA 系统，包括：
- 市场拓展获客
- 案件管理办理
- 财务回款开票
- 行政绩效统计
- 知识库与 AI 分析支撑

### 1.2 技术栈

- **数据库**：PostgreSQL（`law_rag` 数据库，`oa` schema）
- **一体化平台后端**：`law-platform-api`（NodeJS + NestJS + Prisma + TypeScript）—— 业务 API / service / 附件
- **知识库 RAG 后端**：`law-rag-kb`（Python + FastAPI + pymilvus + FlagEmbedding，当前纯函数编排）—— 文档向量化 / 检索 / 问答生成
- **DB 维护工具**：`law-rag-service`（Python + SQLAlchemy + Alembic）—— 仅负责 schema 迁移 / 字典种子 / DB 校验，保留不迁
- **数据文件**：`docs/律所综合业务数据库v2.16_最终冻结版.xlsx`
- **设计文档**：`docs/数据库设计.md`、`docs/平台后端NodeJS开发计划.md`、`docs/RAG开发计划.md`

### 1.3 总体规模

- 源表：83 张
- 统计视图：9 个
- 总字段：1735 个（源表 1588 + 视图 147）
- 关联关系：207 条外键
- 索引：485 个
- 业务阶段：11 个

### 2.3 已修复问题 ✅

在测试过程中发现并修复了以下表字段不匹配问题：

| 表 | 问题 | 修复方式 |
|---|---|---|
| `v_payment_collection_summary` | 发票、退费金额因直接 JOIN 多回款计划而产生笛卡尔积翻倍 | 改为 CTE 先按 case_id 聚合发票、退费后再 JOIN |
| `fin_payment_record` | `payment_amount`/`payment_date`/`receipt_no` 不存在 | 改为 `received_amount`/`received_at`/`bank_flow_no`，补充 `confirm_status` |
| `fin_invoice` | `title` 不存在 | 改为 `invoice_title` |
| `legal_work_log` | `hours_spent`/`billable` 不存在 | 改为 `work_hours`，删除 `bill_result_summary`/`next_step` 等字段按实际调整 |
| `legal_deadline` | `description` 不存在 | 改为 `deadline_title`，补充 `remind_channel` |
| `court_hearing` | `hearing_type`/`hearing_time`/`court_name`/`court_room`/`presiding_judge`/`clerk`/`hearing_status` 不存在 | 改为 `event_type`/`event_time`/`location`/`courtroom`/`judge_or_host`/`result_status` |
| `evidence_item` | `page_count`/`submitted_at`/`submitter_id` 不存在 | 改为 `proof_purpose`/`original_or_copy`/`review_status`/`sort_order` |
| `case_retrieval_task` | 缺少 `review_status` | 补充 `review_status` |
| `ops_ad_creative` | 缺少 `status` | 删除该字段 |
| `crm_consultation` | 缺少 `status` | 删除该字段 |
| `crm_lead` | `key_case_reason` NOT NULL | 非重点案件也提供默认值 |
| `lead_negotiation_record` | `key_case_reason`/`payment_terms_snapshot` NOT NULL | 补充默认值 |
