# 知识库软删除与回收站 — 部署与验收说明

> 日期：2026-07-20
> 配套实现：文档软删除改造 + 独立"回收站"一级模块。
> 计划文件：`~/.claude/plans/kind-crafting-cray.md`

## 一、改动概览

- **普通删除**改为纯软删除：`batchDelete` 只把 `kb_document` / `kb_document_source` 置 `status='deleted'`、`sys_attachment` 置 `status='soft_deleted'`（均写 `deleted_at`），**不**删除 MinIO 原件，**不**调用 RAG 清理。响应改为 `{ deleted, mode:'soft', artifacts_retained:true }`（移除旧 `purged` 字段）。
- **永久删除**：新增 `POST /api/rag/documents/batch-purge`，幂等清理 MinIO 原件 + Milvus chunks + 派生图片 + `kb_document_image` 行，成功后置 `status='purged'`。
- **回收站**：新增 `GET /api/rag/documents/trash`（分页/标题搜索/原分类筛选/按删除时间排序）、`POST /api/rag/documents/batch-restore`（校验原件+图片+向量齐全后原子恢复，原分类失效时需指定新分类）。前端新增独立路由 `/knowledge/trash` 与顶部一级模块"回收站"。
- **去重**：`file_hash` 唯一索引谓词改为 `status IN ('active','soft_deleted')`，回收站存在同文件时阻止重复上传（`409 SOFT_DELETED_DUPLICATE`），`purged` 后释放哈希位允许重新上传。
- **历史数据**：约 152 条已硬删（无原件/向量）的 `deleted` 文档在迁移中统一标记为 `purged`，不进入新回收站。
- **检索安全**：检索授权门 `authorization.py` 已强制 `status='active' AND deleted_at IS NULL`，软删文档天然对 `/search`、`/chat` 不可见，向量仍在但不会被命中。

## 三、严格部署顺序

1. **数据库迁移**：`alembic upgrade head`（新增 revision `f1a2b3c4d5e6`，`down_revision=e9f0a1b2c3d4`）。先回填 `deleted→purged`，再交换 `file_hash` 唯一索引谓词。
2. **RAG 服务**（`law-rag-kb`）：新增 `POST /documents/verify-restore`。现有 `/documents/batch-delete` 语义不变。
3. **平台 API**（`law-platform-api`）：`batchDelete` 改纯软删；新增 trash / batch-restore / batch-purge 端点；去重加软删冲突检查。
4. **前端**（`law-platform-web`）：新增"回收站"导航与页面；更新普通删除弹窗文案。

> 步骤 3 与步骤 4 必须一起上线：旧前端期望 `{deleted,purged}`，新平台返回 `{deleted,mode,artifacts_retained}`（按要求移除 `purged`，无过渡字段）。
> 迁移本身完全向后兼容（无新增列，仅 status 字符串与索引交换；现有代码按 `status='active'`/`'deleted'` 过滤，能容忍 `'purged'`）。

## 四、最终真实验收（仅用 `test_files/rag_test_sample.txt` 一份文档）

1. 上传并等待入库成功 → 确认 `/api/rag/search`、`/api/rag/chat` 命中。
2. 记录基线：DB 行（`status` / `deleted_at`）、`/api/rag/documents/:id/status` 的 `chunk_count`、原件 object_key、派生图片 key。
3. 软删除 → 响应 `{deleted:1, mode:'soft', artifacts_retained:true}`；断言 DB 行 `status='deleted'`、Milvus `chunk_count` 不变、原件 `fileExists=true`、派生图片仍在、`search`/`chat` 对该内容返回 0。
4. 经顶部"回收站"找到并恢复 → 断言文档 ID 不变、`status='active'`、`deleted_at=NULL`、`chunk_count` 不变（同向量，未重嵌）、`search`/`chat` 再次命中。
5. 再次软删 + 永久删除 → 断言 `status='purged'`、Milvus chunks 清空、原件与派生图片删除、`kb_document_image` 行删除、`search`/`chat` 返回 0。
6. 清理：确认系统不遗留该测试文档（无 `active`/`soft_deleted` 哈希残留）。
