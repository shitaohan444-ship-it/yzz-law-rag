# 简单 RAG 前端与局域网测试报告

> 实施与验收日期：2026-07-15  
> 文档补录日期：2026-07-16  
> 结论：简单前端、平台 RAG 基础网关、桌面/手机模拟测试及三项真实 RAG 浏览器验收全部完成。

## 1. 实施范围

本阶段新增 `law-platform-web/`，为已完成的知识库 RAG 提供一个可信局域网验收界面。第一版仅包含：

- 法条检索：展示标题、法条号、章节、相关度和知识库原文。
- 知识问答：展示 Qwen 生成的回答、命中数量和引用原文。
- 无依据保护：检索依据为空时明确显示“知识库依据不足”。
- 页面级会话：同一页面复用 `session_id`，刷新后重新生成，不写浏览器存储。
- 响应式界面：覆盖桌面和手机宽度，并提供键盘焦点、加载和错误状态。

本阶段不包含登录、文件上传、知识库管理、案件私有权限、聊天记录持久化和公网部署。

## 2. 系统调用链

```text
局域网浏览器
    │ HTTP :5173，仅调用相对路径 /api/rag/*
    ▼
law-platform-web（React + TypeScript + Vite）
    │ Vite 代理到本机 127.0.0.1:3000
    ▼
law-platform-api（NestJS 平台网关）
    │ 服务端请求 127.0.0.1:8000
    ▼
law-rag-kb（FastAPI）
    ├── PostgreSQL / MinIO
    ├── BGE-M3 + bge-reranker-v2-m3
    ├── Milvus
    └── qwen3.7-plus（仅知识问答调用）
```

浏览器不直接访问 FastAPI、Milvus、MinIO 或数据库，也不持有 `RAG_SERVICE_TOKEN`。

## 3. 检索与问答的区别

### 3.1 法条检索

```text
问题 → BGE-M3 混合召回 → bge-reranker 精排 → 返回知识库原文
```

法条检索不调用 Qwen 生成答案，但会使用 BGE-M3 进行语义向量检索，并使用 Reranker 对命中片段排序。因此它不是写死结果，也不是普通字符串匹配。

### 3.2 知识问答

```text
问题 → BGE-M3 混合召回 → bge-reranker 精排
     → 把命中片段交给 qwen3.7-plus → 回答 + 引用
```

知识问答在真实检索后调用大模型。引用来自检索命中的知识库片段；没有足够依据时按现有 RAG 策略拒答，不依赖模型自由补充法律结论。

## 4. 平台 RAG 网关

`law-platform-api` 已新增以下浏览器入口：

| 方法 | 路径 | 上游 FastAPI | 用途 |
|---|---|---|---|
| POST | `/api/rag/search` | `/search` | 法条检索 |
| POST | `/api/rag/chat` | `/chat` | RAG 知识问答 |

网关已实现：

- 与 FastAPI 一致的请求长度、`top_k` 和 `doc_ids` 校验。
- 请求字段白名单，浏览器不能伪造内部身份字段。
- 使用 Node 原生 `fetch` 和 `AbortController` 请求 FastAPI。
- 服务端按配置注入内部 Token，空 Token 不发送认证头。
- FastAPI 参数错误使用安全提示；超时映射为 504，连接或无效响应映射为 502。
- 上游详情、服务 Token、供应商信息和密钥不进入浏览器响应。

当前网关属于无登录的局域网验收入口。登录、JWT/Session、当前用户上下文和 `X-RAG-User-Id` 注入仍未完成，因此不能据此开启生产 RAG 鉴权。

## 5. 前端行为与安全

- 页面请求固定为 `/api/rag/search` 和 `/api/rag/chat`，不包含 `:8000` 地址。
- 回答使用 Markdown 渲染，但不启用原始 HTML，模型返回的脚本不会作为页面代码执行。
- 外部链接使用新窗口安全属性。
- 检索和问答的示例问题只负责填充输入框；运行结果来自真实 API。
- `e2e/mock-rag.spec.ts` 中存在写死的模拟响应，仅在 Playwright 模拟测试中通过路由拦截启用，正常页面不会加载该测试文件。
- 前端源码和构建产物扫描未发现内部 Token 或认证头标记。

## 6. 局域网端口边界

验收时的预期监听范围如下：

| 端口 | 服务 | 监听范围 |
|---:|---|---|
| 5173 | Vite 前端 | `0.0.0.0`，供可信局域网访问 |
| 3000 | NestJS 平台网关 | `127.0.0.1` |
| 8000 | FastAPI RAG | `127.0.0.1` |
| 5432 | PostgreSQL | `127.0.0.1` |
| 9000/9001 | MinIO API/Console | `127.0.0.1` |
| 9091/19530 | Milvus HTTP/gRPC | `127.0.0.1` |

Windows 防火墙只需在确有跨设备测试需求时为专用网络放行 TCP 5173，不应放行其余内部端口。

真实浏览器验收用例：

1. `试用期工资最低不能少于多少`：命中《劳动合同法》第二十条。
2. `产品缺陷造成损害生产厂家要赔吗`：生成回答并引用《民法典》第一千二百零二条。
3. `盗窃数额较大的刑事量刑标准是什么`：当前知识库依据不足，界面显示拒答且不展示伪造引用。

## 8. 当前结论与下一步

简单 RAG 前端已经能够通过平台网关真实使用知识库检索和问答，模拟及真实测试均通过。当前适合本机和可信局域网开发验收，不适合公网或不受信任的多用户环境。

下一阶段按顺序推进：

1. 公共知识库上传第一版：MinIO 原件、`kb_document` 登记、自动入库和状态展示。
2. 平台登录、JWT/Session、管理员与普通用户权限。
3. 网关注入内部服务 Token 和已认证 `X-RAG-User-Id`，再启用生产 RAG 鉴权。
