# 企业微信群名解析接入文档（内部群 / 外部客户群）

> 面向接入同事：本文说明如何复用现有的「企业微信群真实名称解析」能力，
> 把会话内容存档里的 `roomid` 解析成可读的真实群名（含群主、人数、群类型）。
>
> - 适用系统：企业微信会话内容存档（msgaudit）相关项目
> - 落地位置：阿里云服务器 `wecom-archive`（root@120.27.160.118）
>   - 工具集项目：`/opt/wecom-msgaudit-puller`（解析核心，Python 3.6 兼容）
>   - 网页后台项目：`/opt/wecom-msgaudit-archive`（Web 展示）
> - 最近更新：2026-07-31（接入内部群解析，已通过真实接口验收）

---

## 1. 背景与目标

企业微信会话内容存档的每条消息里有 `roomid`（形如 `wrwDXRFQAA...`），
但 `roomid` **本身不含群名**，直接展示就是一串无意义 ID。

本能力把 `roomid` 解析为：

| 字段 | 含义 | 示例 |
|---|---|---|
| `room_name` | 真实群名 | `技术部四人小分队` |
| `room_display_name` | 展示用名（= `room_name` 或 `roomid` 兜底） | `技术部四人小分队` |
| `room_type` | 群类型 | `internal`（内部群）/ `external`（外部客户群）/ `unknown` |
| `owner` | 群主 userid | `HuXingDong` |
| `member_count` | 成员数 | `5` |

**两类群都要支持**，且**不能靠 roomid 前缀判断内外群**（内部群和外部群的
roomid 都可能以 `wr` 开头），必须以接口查询结果为准。

## 2. 两个企业微信接口（核心）

### 2.1 外部客户群 → 客户联系接口

```
POST https://qyapi.weixin.qq.com/cgi-bin/externalcontact/groupchat/get?access_token=XXX
Content-Type: application/json

{ "chat_id": "<roomid>", "need_name": 0 }
```

成功响应（节选）：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "group_chat": {
    "chat_id": "wrwDXRFQAA...",
    "name": "测试test",
    "owner": "HanShiTao02",
    "create_time": 0,
    "notice": "",
    "member_total": 3,
    "member_list": [ ... ]
  }
}
```

字段映射：`group_chat.name → room_name`、`group_chat.owner → owner`、
`group_chat.member_total → member_count`、`create_time → create_time`、`notice → notice`。

### 2.2 企业内部群 → 会话内容存档接口

```
POST https://qyapi.weixin.qq.com/cgi-bin/msgaudit/groupchat/get?access_token=XXX
Content-Type: application/json

{ "roomid": "<roomid>" }
```

成功响应（节选）：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "roomname": "技术部四人小分队",
  "creator": "HuXingDong",
  "room_create_time": 1700000000,
  "notice": "",
  "members": [ {"userid": "..."}, ... ]
}
```

字段映射：`roomname → room_name`、`creator → owner`、
`members 数组长度 → member_count`、`room_create_time → create_time`、`notice → notice`。

> ⚠️ 注意：两个接口**请求体字段不同**——外部用 `chat_id`，内部用 `roomid`；
> **响应结构也不同**——外部群名在 `group_chat.name`，内部群名在顶层 `roomname`。
> 不要混用。

## 3. 凭据与 access_token（两类必须分开）

### 3.1 需要的三个配置项

| 环境变量 | 用途 |
|---|---|
| `WECOM_CORP_ID` | 企业 CorpID（两个接口共用） |
| `WECOM_EXTERNAL_CONTACT_SECRET` | 外部客户群接口凭据（客户联系 Secret） |
| `WECOM_MSGAUDIT_SECRET` | 内部群接口凭据（会话内容存档 Secret） |

### 3.2 取 token

```
GET https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=<CorpID>&corpsecret=<Secret>
```

- **外部群 token**：用 `WECOM_EXTERNAL_CONTACT_SECRET` 换。
- **内部群 token**：用 `WECOM_MSGAUDIT_SECRET` 换。
- 两者**完全分开缓存、互不混用**（内部群绝不能用 EXTERNAL_SECRET 查）。

### 3.3 token 管理规则

1. 按返回的 `expires_in` 缓存（默认 7200s）；
2. **提前 5 分钟**（300s）视为临期，自动刷新；
3. 遇到 token 失效 errcode（`40014 / 42001 / 42007 / 40001`）→ 清缓存重取，
   **对当前请求只重试一次，不无限重试**；
4. token 只保留在内存，**不写 .env、不落盘、不写进任何缓存文件**；
5. 并发下用锁避免重复取 token。

## 4. 统一解析流程（级联顺序）

对外只暴露一个统一入口 `resolve_group_info(roomid)`，内部按下面顺序处理：

```
roomid 为空（单聊消息）
  └─ 直接返回，不调用任何远程接口

先查本地缓存
  ├─ 缓存已确认 external / internal → 直接用缓存，不再请求
  └─ 缓存未确认 / 已过期 → 走远程

远程查询（未知 roomid）
  1) 调外部群接口 externalcontact/groupchat/get
     ├─ errcode = 0            → room_type = external（即便群名为空也算确认外部群）
     └─ errcode = 90501        → 「不是外部群」，转第 2 步
  2) 调内部群接口 msgaudit/groupchat/get
     ├─ errcode = 0            → room_type = internal，room_name = roomname
     └─ errcode = 301059       → 「不是内部群」
  3) 两个接口都确认不了
     └─ room_type = unknown，room_name = null

最终展示字段
  room_display_name = room_name  or  roomid
```

### 4.1 关键错误码

| errcode | 含义 | 处理方式 |
|---|---|---|
| `0` | 成功 | 取群名 |
| `90501` | 该群不是外部客户群 | **级联信号**：转内部群接口，不算故障 |
| `301059` | 该群不是内部群（only support inner room） | 记录为非内部群，回退 `unknown`，**不抛异常** |
| `60011` | 无权限访问该客户群 | 记录失败（`external_no_privilege`），回退，不中断 |
| `40014/42001/42007/40001` | token 失效 | 刷新 token 重试一次 |
| 网络超时/其它 | — | 返回失败结构，**绝不中断消息主流程 / 页面加载** |

> ⚠️ 所有失败都返回统一的失败结构，**不向上抛异常**——单个群查询失败
> 绝不能影响解密、拉取、或群列表页面的加载。

## 5. 统一返回结构

成功（内部群）：

```json
{
  "roomid": "wrwDXRFQAAsL4oJ8yndZeG0WkLRPiHYQ",
  "room_name": "技术部四人小分队",
  "room_display_name": "技术部四人小分队",
  "room_type": "internal",
  "owner": "HuXingDong",
  "member_count": 5,
  "query_success": true,
  "error_code": 0,
  "error_message": null
}
```

失败（统一兜底，不抛异常）：

```json
{
  "roomid": "wrxxx",
  "room_name": null,
  "room_display_name": "wrxxx",
  "room_type": "unknown",
  "owner": null,
  "member_count": null,
  "query_success": false,
  "error_code": 301059,
  "error_message": "only support inner room"
}
```

**展示规则**（前端/导出统一）：

```js
const displayName =
  room.room_display_name || room.room_name || room.roomid || "未知群聊";
```

`room_name` 为空时**禁止**显示 `null` / `undefined` / 空白标题，回退 `roomid`。
`roomid` 字段**永远保留**，供详情查看、调试、数据关联。

## 6. 缓存设计

> 目的：同一 roomid 全系统只真正请求一次远程接口，避免每条消息都打一次。

**缓存键**：`roomid`（唯一）。

**单条记录字段**：

```
roomid, room_name, room_type, owner, member_count,
create_time, notice, query_success,
error_code, error_message, updated_at, expires_at
```

**TTL 分级**：

| 情况 | 缓存时长 |
|---|---|
| 查询成功（有群名） | 24 小时 |
| 群名为空 | 30 分钟 |
| 查询失败 | 5 分钟 |

**规则**：

1. 支持 `force_refresh` 强制刷新（绕过缓存）；
2. 已确认 `room_type` 后，后续直接命中缓存，不再请求；
3. **缓存里绝不保存 Secret 和 access_token**（写入前主动剔除）；
4. 缓存文件写入用「临时文件 + 原子替换 + 文件锁」，防并发损坏。

## 7. 现成可复用的代码（直接调用即可）

### 7.1 工具集项目 `/opt/wecom-msgaudit-puller`

核心模块 `wecom_external_group.py`（文件名沿用历史，内部群能力也在里面）：

```python
import wecom_external_group as weg

# 统一入口（推荐）：内部群/外部群自动级联，缓存优先
info = weg.resolve_group_info(roomid)                  # 返回上面第 5 节的结构
info = weg.resolve_group_info(roomid, force_refresh=True)  # 强制刷新

# 只取群名（失败/为空返回 None，由调用方兜底 roomid）
name = weg.resolve_group_name(roomid)

# 展示名统一逻辑：room_name or roomid or "未知群聊"
display = weg.build_room_display_name(info.get("room_name"), info.get("roomid"))

# 单独取 token（一般不用直接调，resolve 内部已处理）
weg.get_external_contact_access_token()
weg.get_msgaudit_access_token()
```

消息接入点：`pull_once.py` 的 `build_group_info(roomid)` 已走统一入口，
解密后的 `summary` / `normalized_message` 自带 `room_name / room_display_name /
room_type / room_owner`，**roomid 不被覆盖**。

历史数据补全脚本：

```bash
# 内部群
python3 scripts/backfill_internal_group_names.py --dry-run          # 只统计不请求
python3 scripts/backfill_internal_group_names.py --roomid wrw...    # 指定单个
python3 scripts/backfill_internal_group_names.py --limit 10
python3 scripts/backfill_internal_group_names.py --force-refresh
# 外部群
python3 scripts/backfill_group_names.py --dry-run
```

测试（全部离线 mock，不触网、不读真实 secret）：

```bash
cd /opt/wecom-msgaudit-puller
python3 -m unittest discover -s tests        # 39 个测试（23 外部 + 16 内部）
```

### 7.2 网页后台项目 `/opt/wecom-msgaudit-archive`

模块 `app/wecom_room_name.py`（供 `health_server.py` 使用）：

```python
import wecom_room_name as w

# 批量解析（网页群列表用），三层回退：DB手工名 > 外部/内部接口 > roomid
names = w.resolve_room_names(roomids, manual_names=manual, persist=persist_cb)

```

网页接口 `/internal/archive/rooms` 返回每个群：

```json

  "roomid": "wrwDXRFQAA...",
  "room_name": "技术部四人小分队",
  "room_display_name": "技术部四人小分队",

  "msg_count": 28,
```

> archive 侧 `room_type` / `room_owner` 目前为 `null`（该项目的解析器只回传群名）；
> 类型/群主信息以 puller 侧 `resolve_group_info` 为准。如需网页也显示类型，
> 让 archive 的解析器回传 `room_type`/`owner` 即可。

## 8. 凭据注入方式（两套项目不同）

| 项目 | 读取方式 |
|---|---|
| puller（CLI） | 从 `/opt/wecom-msgaudit-puller/.env` 读 `WECOM_CORP_ID` / `WECOM_EXTERNAL_CONTACT_SECRET` / `WECOM_MSGAUDIT_SECRET` |
| archive（Docker 容器） | 从 secret 文件读，经环境变量传路径：`WECOM_CORP_ID_FILE` / `WECOM_EXTERNAL_CONTACT_SECRET_FILE` / `WECOM_MSGAUDIT_SECRET_FILE` |

> ⚠️ archive 容器以非 root（uid 10001）运行，secret 文件权限须为 **644**，
> 否则容器读不到 → `internal_available()` 返回 False，内部群名解析静默失效。

## 10. 安全红线（接入时务必遵守）

1. **绝不**在源码、日志、异常、测试输出里打印完整 Secret 或 access_token；
2. token 只留内存，不写 .env、不落盘、不进缓存文件；
3. 缓存文件里绝不保存 Secret / access_token；
4. 不靠 roomid 前缀判断内外群，一律以接口结果为准；
5. 任何单群查询失败都不抛出、不中断消息主流程 / 页面加载；
6. 修改后不重置 `data/seq.txt`、不删历史消息、不破坏现有外部群功能。
